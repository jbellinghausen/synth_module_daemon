# synth_module_daemon

A Raspberry Pi daemon that drives CV/gate (GPIO + MCP4728 DACs), clock/run
outputs and USB MIDI, plus client libraries for talking to it from Python and
from the browser. Split out of the
[ai_midi](https://github.com/jbellinghausen/ai_midi) sequencer.

```
synth_module_daemon/
  PROTOCOL.md          wire protocol (the contract between daemon and clients)
  daemon/              the Pi service: hw_daemon.py, install.sh, systemd unit
  clients/python/      Python client (pip package: synth-module-client)
  clients/js/          JS/browser client (npm package: synth-module-client)
  tests/               Python + JS tests, run against a dry-run daemon
  example_prompts/     prompts for building apps on the module with an AI coding assistant
```

## Using the clients

### Python

```bash
pip install "git+https://github.com/jbellinghausen/synth_module_daemon.git#subdirectory=clients/python"
```

```python
from synth_module_client import SynthModuleClient, discover

print(discover())  # find daemons on the LAN

with SynthModuleClient("raspberrypi.local") as synth:
    synth.cv_note_on(slot=0, note=48, velocity=100)
    synth.cv_gate_off(slot=0)
    synth.midi_note_on(channel=0, note=60)
    synth.clock_start(120)
```

See [clients/python/README.md](clients/python/README.md).

### JavaScript / browser (three.js apps etc.)

```bash
npm install github:jbellinghausen/synth_module_daemon
```

```js
import { SynthModuleClient } from 'synth-module-client';

const synth = await new SynthModuleClient('raspberrypi.local').connect();
synth.cvNoteOn(0, 48, 100);
setTimeout(() => synth.cvGateOff(0), 250);
await synth.clockStart(120);
```

No bundler? It's a single dependency-free ES module, so you can also copy
`clients/js/synth-module-client.js` into your project and import it directly.

**See the [web apps guide](clients/js/README.md)** for serving requirements,
reconnecting, CV/MIDI details, timing tips, three.js and React examples, and
troubleshooting.

Browsers connect over plain `ws://` on port 9743, so the page must be served
over `http://` (or from localhost): browsers block `ws://` from `https://`
pages. Browsers can't do UDP discovery, so pass the Pi's hostname or IP.

## Setting up a new Pi

### 1. Flash the OS

Use Raspberry Pi Imager to flash **Raspberry Pi OS (64-bit)**, Bookworm or
later. Lite is fine. In the Imager's settings, set the **hostname** (clients
connect to `<hostname>.local`, e.g. `raspberrypi.local`), your user and
password, Wi-Fi if needed, and enable SSH.

64-bit matters: every dependency installs from prebuilt packages on 64-bit
Pi OS. On 32-bit, pip may have to compile `lgpio` and `python-rtmidi` from
source.

### 2. Hardware

- DACs on I2C bus 1 (MCP4728 at 0x60, 0x61, 0x62), gates, clock (GPIO 18)
  and run (GPIO 15) as in [Hardware config](#hardware-config).
- **Loopback jumper: GPIO 4 → GPIO 23.** The clock output is generated by
  counting pulses on this loop. Without it, CLK never pulses; everything else
  works.
- USB MIDI interface in any USB port. It can be plugged in before or after
  boot.

### 3. Install

```bash
sudo apt install -y git    # if not already installed
git clone https://github.com/jbellinghausen/synth_module_daemon.git
cd synth_module_daemon
daemon/install.sh
```

`install.sh` does everything else, and is safe to re-run:

- installs `python3-venv` if missing, and **enables I2C** via `raspi-config`;
- creates `venv/` with the daemon's dependencies and the client package
  (which holds the shared protocol module);
- installs the pre-made system config from `daemon/systemd/`:

  | Installed to | What it does |
  |--------------|--------------|
  | `/etc/systemd/system/hw-daemon.service` | The daemon. Starts at boot once ALSA is up (no wait for the network), restarts on failure, runs as your user with `gpio`/`i2c`/`audio` access |
  | `/etc/default/hw-daemon` | Daemon options (`HW_DAEMON_ARGS`). Created once; your edits are kept on re-install |
  | `/etc/udev/rules.d/90-hw-daemon-midi.rules` + `hw-daemon-midi-rescan.service` | Restarts the daemon ~2 s after a MIDI device is plugged in or removed, so the device list stays current |

- enables and starts the service, and checks that it came up.

### 4. Check it

```bash
systemctl status hw-daemon     # should be "active (running)"
journalctl -u hw-daemon -b     # DACs, MIDI outputs and listening ports
sudo reboot                    # then check status again: it starts by itself
```

The daemon starts as soon as the sound system is ready rather than waiting
for the network. How long that takes depends on the rest of the boot: extra
services such as snapd can add minutes.

From another machine, `python -c "from synth_module_client import discover;
print(discover())"` (with the Python client installed) should list the Pi.

### Updating

```bash
cd synth_module_daemon
git pull
daemon/install.sh    # picks up new dependencies and config, restarts the daemon
```

### Uninstalling

`daemon/install.sh --uninstall` removes the service and udev rule (it leaves
`/etc/default/hw-daemon` and the repo in place).

## Running the daemon

### Managing the service

```bash
systemctl status hw-daemon
journalctl -u hw-daemon -f
sudo systemctl restart hw-daemon
```

### Options

Daemon options live in `/etc/default/hw-daemon`:

```bash
sudo nano /etc/default/hw-daemon     # e.g. HW_DAEMON_ARGS="--log-level DEBUG"
sudo systemctl restart hw-daemon
```

Or set them while installing (this overwrites the file):

```bash
HW_DAEMON_ARGS="--config hw_config.json --log-level DEBUG" daemon/install.sh
```

Relative paths are resolved from the repo root. See all options with
`venv/bin/python daemon/hw_daemon.py --help`.

### Running manually

```bash
./venv/bin/python daemon/hw_daemon.py              # real hardware
./venv/bin/python daemon/hw_daemon.py --dry-run    # log commands, no GPIO/DAC
./venv/bin/python daemon/hw_daemon.py --no-websocket
./venv/bin/python daemon/hw_daemon.py --config hw_config.json
```

Stop the service first (`sudo systemctl stop hw-daemon`) when running manually
against real hardware: GPIO pins and ports can only be held by one process.
Running manually needs your user in the `gpio`, `i2c` and `audio` groups (the
default user on Raspberry Pi OS already is); the service gets these itself.

### Hardware config

Without `--config`, the built-in `DEFAULT_CONFIG` in `daemon/hw_daemon.py` is
used (12 CV/gate slots across three MCP4728 DACs at 0x60–0x62, clock on GPIO
18, run on GPIO 15). Supply a JSON file with the same shape to override it.

### Behavior notes

- CV pitch is 1 V/octave with note 24 = 0 V. The 3.3 V DACs limit the usable
  range to **notes 24-63**; out-of-range notes are clamped silently (no
  error), so they sound stuck on the lowest or highest note.
- One client at a time, across TCP and WebSocket together. Others are refused.
- On disconnect the daemon sends all-notes-off, stops the clock and drops the
  run signal.
- MIDI outputs are enumerated at startup. The udev rule installed by
  `install.sh` restarts the daemon when a MIDI device is plugged in or
  removed, which briefly disconnects the current client.

## Protocol

See [PROTOCOL.md](PROTOCOL.md). When changing it, update
`clients/python/synth_module_client/protocol.py` (used by the daemon and the
Python client) and `clients/js/synth-module-client.js`, and bump the version
in `clients/python/pyproject.toml`, `clients/python/synth_module_client/__init__.py`
and `package.json`.

## Tests

```bash
./venv/bin/python -m unittest discover -s tests   # daemon, Python client, protocol sync
npm install && npm test                            # JS client (Node 18+)
```

Tests run the daemon in dry-run mode on ephemeral ports, so they don't need
hardware and don't clash with a running service.
